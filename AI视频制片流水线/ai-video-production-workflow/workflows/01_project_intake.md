# Project Intake

Use when the user gives a video idea, goal, script fragment, product, topic, or reference.

Collect or infer:

- video type and purpose
- target audience and platform
- aspect ratio and duration
- tone, style, references, and must-avoid items
- required characters, scenes, props, and key moments
- what the user will generate externally

Output:

- Create or update `00_brief/PROJECT_BRIEF.md`.
- List next required workflows.
- Mark assumptions separately from confirmed user input.

Routing after intake — intake registers the project, it does not develop the story:

- Only an idea/mood/topic, no script → `01B_story_development.md` to develop concept, beats, and script before any storyboard work.
- Wants the style of an existing work (not a 1:1 copy of one video) → `15B_style_study.md`.
- Provides a specific video to copy shot-for-shot → `15_reference_video_reverse_engineering.md`.
- Already has a storyboard/shot list → `06B_storyboard_intake.md` (audit, don't re-break).

Quality gate:

- The brief must make the next production step obvious.
- Do not create final shots until project direction is sufficiently locked.
- Do not hand a raw idea to storyboard breakdown; story development comes first.
