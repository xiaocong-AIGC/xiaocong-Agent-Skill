# Story Development

Use after project intake when the user has only an idea, mood, topic, or fragment — no script yet. Intake registers the project; this workflow develops the story. Do not hand a raw idea to storyboard breakdown.

## Process

1. Concept: write logline (one sentence: protagonist + want + obstacle + hook), genre, theme, core emotional promise, and 2-3 comparable works. Confirm with the user before expanding.
2. Beat sheet: structure the story with clear turning points. For short-video platforms, the hook must land within the first 3 seconds of screen time. Every setup must have a planned payoff (Chekhov's gun rule).
3. Script: scenes with location/time headers, action lines (visual, filmable, concrete), and dialogue.
4. Dialogue rules: natural speech with subtext — no slogans, no preaching, no AI-flavored lines; each character has a distinguishable voice (blind test: cover the names, can you tell who speaks?); every line must survive "delete it — does the story still work?"; lines that can be replaced by an image should be.
5. Mark planned high-risk moments (crowd scenes, complex action, effects) early so asset and budget planning can see them.
6. Each scene must have: who wants what, what blocks it, what changes by the end of the scene.

## Output

- Save `00_brief/Pxxx_CONCEPT_vNN.md` (logline, beats) and `00_brief/Pxxx_SCRIPT_vNN.md`.
- Route the finished script to `06_storyboard_breakdown.md`.

## Quality gate

- The logline works as one sentence with a visible hook.
- The beat sheet has at least one real turn; the emotional curve is not flat.
- No unfired Chekhov guns; no orphan payoffs.
- Dialogue passes the naturalness and voice-distinction checks.
- The ending finishes the story rather than stopping it.
