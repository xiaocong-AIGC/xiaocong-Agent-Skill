# MiniMax H3 通用视频提示词流水线

把用户的一个想法，经带确认门的阶段，变成可直接投入 Midjourney、GPT Image 2、MiniMax H3、Suno 的提示词资产链。题材通用。

## H3 提示词哲学（全流程总纲）

H3 对参考图的理解力极强，正确分工是：**参考图承载内容，文字只声明读图方式与表演**。故事板负责场景、机位、节拍；角色板负责外观；视频提示词只做三件事——声明怎么读图、给台词、定音频分工。这与"用文字重述一切"的模型（Seedance 流程）方向相反，整条链的所有设计都服务于此：故事板画不清楚的东西，成片里就没有，因为视频提示词不会兜底。

## 模式分流

进入阶段 0 前先判断：

- **模式 A｜参考图驱动流**：有角色、或需要跨镜头一致性的叙事片 → 走五阶段资产链
- **模式 B｜纯文本流**：无固定角色的概念动画/动态设计/风格化序列（城市地图、图形演绎、物件蒙太奇等）→ 概念定稿后直出一条纯文本提示词，读 `references/h3-text-template.md`
- 混合变体：模式 B 文本 + 单张角色/风格参考，见 h3-text-template.md 末节

## 模式 A 流程总览

| 阶段 | 产出 | 推进条件 |
|---|---|---|
| 0 故事定稿 | 故事 + 节拍表（N ∈ {6, 9, 12, 16}）+ 台词标注（中文） | 用户确认剧本 |
| 1 风格与角色探索 | Midjourney 每角色全身图提示词 + 风格候选 | 用户跑图选定 |
| 2 资产生产 | 每角色一张设定板 + 按清单的场景图资产 | 用户做完资产 |
| 3 分镜故事板 | GPT Image 2 提示词（每单元一板） | 用户做完故事板 |
| 4 视频 + 音乐 | H3 提示词 + Suno 纯音乐提示词 | 交付，按验收清单迭代 |

**一次只推进一个阶段。** 每阶段输出后明确停下，告诉用户"确认后进入下一步"。不要因为内容都能推导出来就一口气全给——用户要拿每阶段产物去外部工具实际生成图/板，下一阶段的提示词依赖那些真实产物。

**判断当前阶段。** 用户可能中途进入（"角色板做好了"、"直接给我 H3 提示词"）。根据用户的话和已有存档判断处于哪个阶段，从那里继续；缺上游信息就先要（如：还没有确认的剧本，就先回到阶段 0）。

## 全局规则

1. **内容全推导，模板只借格式。** references/ 与案例库给的是段落结构和措辞方式；片名、角色、节拍、风格词全部从本次确认的故事推导。绝不把模板或案例里的具体内容带进产出。
2. **P## 贯穿链。** 节拍表 P## → 故事板 Panel ## → H3 "follow each panel as a separate beat" 逐格执行。面板数 = 节拍数，从 {6, 9, 12, 16} 中选（16:9 板上分别对应 3×2 / 3×3 / 4×3 / 4×4 排布，都能读得干净）。上游任何修改都要同步整条链。
3. **资产链单向引用。** MJ 图 → 角色板 / 场景图 → 故事板 → H3 视频。每阶段引用上一阶段真实产物作参考图；引用只声明用途，**绝不重述参考图里已锁定的内容**——重述会让文字与图打架导致漂移。H3 视频提示词零场景描述、零逐拍重述（铁律与逐字措辞见 h3-video-template.md）。
4. **语言分工。** 与用户沟通、故事、节拍表用中文；给工具的提示词一律英文；**台词/旁白语言按目标观众定**（阶段 0 与用户确认，不默认中文或英文）。
5. **台词时长校验。** 语速估算：中文约 4–5 字/秒、日文约 6–7 音/秒、英文约 2–3 词/秒。台词所在拍的时长必须容纳该句并留呼吸；全片台词总时长逼近叙事窗口时回改剧本，宁可删句不可赶话。
6. **落盘存档。** 在当前工作目录建 `<项目代号>/`，每阶段产出同时写入文件（结构见文末），方便中途接续和复盘。

## 阶段 0｜故事与节拍（模式 A）

输入是一句想法。输出全中文，结构：

- **片名**（中文 + 英文）、**Logline** 一句话
- **情绪基调**：2–4 个形容词——它是贯穿故事板与成片的统摄透镜（如：亲密、克制、微微忧郁），后续所有阶段的氛围措辞都从这里推导
- **场景清单**：本片出现的全部"地点 × 时刻"组合，每个场景一两句钉死（空间类型、关键物件、光线时刻）；大空间带尺度数字（宽度/纵深/高度），没有数字的场地模型默认画窄
- **角色速写**：0–3 个。每个给名字、身份、外形关键词（发型/头饰/服装块面/体型）、表演气质、视觉签名（最可识别的视觉标志：配色、剪影件、标志道具）。0 角色写清叙事主体是什么
- **节拍表**：N 从 {6, 9, 12, 16} 选——抒情/生活流 6–9，标准叙事 9–12，高密度快节奏 12–16。每拍一行：

  `P01 | 0.0–1.8s | 镜头要点 | 单一动作/情绪瞬间 | 台词（若有：谁说 + 内容 + 语气）`

  时间加总 ≤ 15 秒。**节拍时长要不均匀**：重点拍给长、过渡拍压短——节奏起伏是成片"不显平"的来源。每拍必须是可画成单格的静态可读瞬间。
- **收束**：最后一拍是全片记忆点（情绪落点/揭示/反转），给足时长
- **压信息设计**（可选）：某个关键视觉要压到最后才可读的（成品图案、真相、标题），在此标注——它会进入故事板的信息节奏控制行

若想法装不进 15 秒，先与用户确认总时长，按多单元拆分（读 `references/h3-multi-unit-guide.md`）：单元叙事 ≤13 秒 + 2 秒余量，节拍按单元分组，边界按剪辑点规则设计，**台词不跨单元边界**。

输出后停：请用户确认或提修改。节拍表一经确认，P## 编号即锁定。

## 阶段 1｜风格与角色探索（唯一的发散阶段）

本阶段的职责是**发散**：定风格、定角色形象，用 MJ（审美方差大，适合探索）。产出两类东西：**风格定义段**（从选定候选提炼的英文媒介措辞块——只写写实等级/镜头感/氛围体积感/调色哲学/材质细节，**不写具体颜色**；它是全片统一感的唯一来源，后续每条图像提示词逐字复用）+ 每角色一张全身形象图。**三句分工铁律：文字管风格（统一风格段逐字复用），描述管内容（各场景构图、色调、光线按内容自由写），参考图只管身份与关键帧（同一角色/身体件/场景的复现、视频首帧）——绝不用参考图锁风格，风格参考图会把锚图的色调错误强加给色调本不同的场景。**

每个主要角色一条，出一张全身形象图——它是阶段 2 角色板的 reference image：

```
Midjourney: full body view of {角色描述——体型、发型/头饰、服装块面、标志性道具、姿态气质}, illuminated by {光线与氛围，从场景清单推导}. --ar 2:3 --stylize 1000
```

- 全身完整可见、单人、不裁切；脸型、发型轮廓、服装剪影必须清楚——后续所有资产的相貌一致性都源自这张图
- 风格方向未定时，先出 2–3 条不同风格措辞的候选（写实电影质感 / 动漫 / 手绘水彩……）；用户选定后，把该候选的媒介措辞提炼为**风格定义段**
- 0 角色项目：只做风格候选（拿本片第一个场景当题材出 2–3 条），选定后提炼风格定义段

输出后停：等用户选定风格方向与各角色形象图。风格定义段一经锁定，全片逐字复用。

## 阶段 2｜资产生产（角色板 + 场景图）

- **角色板**：读 `references/character-board-template.md`，每角色一条独立提示词（reference image = 该角色选中的 MJ 图）
- **场景图资产**：读 `references/scene-asset-guide.md`，从场景清单 + 节拍表推导需要哪些图（地点 × 时刻 × 机位），用 **GPT Image 2 完整描述直出**（构图 + 该场景自己的光色 + 统一风格段）——不用 MJ、不挂风格参考图。本流水线**不做环境识别板**，场景以图资产直接进故事板
- 0 角色项目：只出场景图

输出后停：等用户做完全部资产。

## 阶段 3｜分镜故事板（GPT Image 2）

读 `references/h3-storyboard-template.md`。每单元一条提示词、一张 16:9 板，面板数 = 该单元节拍数（∈ {6, 9, 12, 16}）。参考图 = 角色板（在前）+ 该单元场景图（在后），上传顺序与提示词映射一致。

输出后停：等用户做完故事板。

## 阶段 4｜H3 视频 + Suno

读 `references/h3-video-template.md`。交付 H3 视频提示词（多单元片逐单元、串行）+ Suno 纯音乐提示词。交付后按模板里的"生成验收与定向重试"清单迭代；用户此时要改剧情或分镜，提醒需回到对应上游阶段并同步 P## 链。

## 模式 B｜纯文本流

阶段 0（概念定稿，中文，输出后停等确认）：主体与参数、世界设定、情绪透镜、镜头与速度曲线设想、动效语言方向、收尾与落版设计。确认后读 `references/h3-text-template.md` 出英文提示词，交付后按需微调。

## 案例库

`references/case-library.md` 存有本 skill 结构来源的两个原案例全文，供措辞风格参照。只借结构与措辞方式，绝不把案例具体内容（拿铁、城市地图、任何具体意象）带进产出——除非用户的题材恰好如此。
